# Phase 3.5 Gates 1-3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the locally verifiable Phase 3.5 trust-boundary gaps, exercise Provider contracts, and make Recovery/CI evidence reproducible without falsely promoting external blockers.

**Architecture:** Keep the Kernel as the only owner of operation identity, durable transitions, cancellation state, and reconciliation. Keep Provider live qualification and operator recovery drills as explicit evidence-producing adapters around the Kernel. Phase 6 resource/router/scheduler implementation remains out of scope until the Gate checker reports no actionable Phase 3.5 items.

**Tech Stack:** Python 3.10 standard library, pytest, SQLite/JSON StateStore, subprocess process isolation, GitHub Actions, JUnit XML.

**Spec:** `dev_agent_codex_4docs/02_dev_agent_foundation_requirements.md`, `dev_agent_codex_4docs/03_dev_agent_v2_current_roadmap_simple.md`, `dev_agent_codex_4docs/04_dev_agent_v2_current_roadmap_companion.md`, `spec/v2/GATE_STATUS.json`.

## Global Constraints

- PASS is reserved for `VERIFIED`; `IMPLEMENTED` and `INTEGRATED` remain actionable.
- External timeout, lost response, decode failure, output-schema failure, or local persistence uncertainty after dispatch must become reconciliation-required.
- Trusted in-process Python handlers retain a documented soft timeout; untrusted/generated/process handlers use subprocess isolation and process-tree termination.
- Every behavior change is developed test-first: write a failing test, observe the expected failure, implement the smallest fix, then run focused and full verification.
- Do not begin Phase 6 Resource/Budget/Router/Survival/Scheduler implementation in this plan.
